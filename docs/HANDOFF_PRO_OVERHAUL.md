Status as of 2026-09-26 (second pass: shared editor switcher). Read this first if you are picking the redesign up.

Design rules that came out of the rounds (user feedback):
- AI-first by chat and voice, **but fully manual too**; pro-level, still easy.
- When the AI acts it must **name/show on the plan or model the parts it picked**, so the user can confirm or choose (lettered candidates when unsure).
- Show the whole flat, not one room; layers; a clear screen to judge the AI and fix it by hand.
- Devices: desktop, phone 390×844, Fold7 open 832×750, wide fold open 890×626 CSS (2670×1878) and its cover 466×678 (1398×2034).
- Never fake a tool: a button either runs a real feature or says it is not built.

## What is implemented

The "all pro tools" layer — built on top of the existing editors, not a rewrite:

- `js/pro_catalog.js` — every tool of all three editors (editor → tab → group → tool), each with one binding to a real feature (`tool:`, `act:`, `run:`, `click:`, `reveal:`, `left:`, `lib:`, `pro:`, `mcmd:`, `mrel:`, `mcon:`, `meng:`, `mclick:`, `cab:`, `mep:`, `nest:`/`nestgo:`). Hebrew for every string (`PRO_HE`, `proLabel`).
- `js/pro_ribbon.js` + `css/pro_ribbon.css` — desktop planner ribbon (editor switch, 9 tabs, Ask box with voice → exact tool name runs it, else `askAgent()` in `ui_agent.js`), the "All tools" section of the phone Tools sheet, and model-editor/cabinet commands in ⌘K.
- `js/pro_actions.js` — commands for features that had no entry (sheet print/SVG, DXF, IFC, schedules, clearances …).
- `tests/pro_catalog.test.mjs` — every binding must resolve to real code, every icon must exist, every model-editor ribbon command must be in the catalog, every string needs Hebrew, and **no `planned:` tool may remain**.
- `docs/PRO_TOOL_GAPS.md` — all 30 former gaps are closed (see that file for notes, e.g. "Send to shop" is a review package, not a machine release).
- `js/pro_shell.js` — **one editor switcher (Planner · Model · Cabinet) in all three editors**: the planner ribbon, the model editor header and the cabinet designer header mount the same `editorSwitchHTML()`. No editor is imported there: each registers `open / isOpen / leave / canOpen / why` (`modeler_launch.js` opens the model editor lazily, `modeler.js` adds `leave` = the Close path with its unsaved-changes question, `ui_cabinet.js` registers the cabinet designer; leaving it is Done, not Revert). A target that cannot open (Cabinet with nothing selected) says why and does not close the current editor. Short labels (Plan · Model · Cabinet) at ≤1100px, 40px pills on touch layouts, and the editor's own title is screen-reader-only because the active pill names it (as in the mockups). `tests/pro_shell.test.mjs` covers the order, refusals and the three mounts.
- **Phone / fold planner strip** (`#m-editor-strip`, built in `js/mobile_shell.js`): a 44px row under the compact top bar with the same switcher (Plan · Model · Cabinet) and 2D · 3D · Split. Panes go through the shell's own `setView()` (drops a half-armed draw tool, returns an elevation to the top-down plan), and the nav's View slot and the strip stay in sync. `--mobile-topbar-block` is now `--mobile-topbar-row + --m-editor-strip`, so every fixed drawer/sheet below the chrome moved down with it; the top bar keeps `--mobile-topbar-row`. The strip sits at the top bar's z-index (100), above the sheet backdrop. It is dropped (and the block shrinks) at `max-height: 500px` (a phone on its side) and in the full-screen game modes. A narrow desktop window (768–1023px, no touch) — where the ribbon is hidden — shows the strip with the switcher only.

- **Round-6 shell** (`js/pro_shell.js`, desktop ≥1024px; phones keep their sheets). Each piece is markup + wiring; what it acts on comes from `registerShell()`, which `js/pro_ribbon.js` fills from the planner (project name, AI helper, pro catalog):
  - **Project name** — inline rename of `S.workspace.name` (Enter saves and marks the plan dirty, Esc cancels; read-only for the `viewer` role). Planner: on the ribbon's first row before the switcher (the planner top bar's centre has no room). Model editor / cabinet designer: in their headers.
  - **AI switch** (`aiOn()`, localStorage `mf.proShell.ai`, default on). Off = fully manual: the bottom bar and the phone Ask box only run tools by name and never reach the AI helper; the status chip says "AI off · fully manual". The helper's own button still opens it on request.
  - **Share** — opens the project dialog on its Collaborate tab (`openWorkspace("collaborate")`).
  - **Bottom "AI | › Cmd" bar** in all three editors. Cmd: suggestions from that editor's pro catalog as you type (↑/↓, Enter runs), an exact name runs directly, anything else says "No tool called …". AI (planner only): same as the old ribbon Ask box — a tool name runs it, other text goes to `askAgent()`. In the model editor and cabinet designer the AI segment is disabled and says why (the helper acts on the plan only). Voice input is shared (`wireVoice`). Typing never fires editor shortcuts.
  - **The bar fits itself** (`fitCommandBar` in `js/pro_shell.js`): the planner's floating chrome in its row — an open Layers panel, the gizmos, the 3D navigation bar, the bottom tool strip — is the user's choice, so the bar takes the widest free span of its row and, where a strip spans the whole width, steps up past the lowest blocker only. It refits on resize, view-mode changes and tool-panel changes, and publishes `--ps-bar-clear` so the 2D and 3D hints stand above it. Checked clean in plan / 3D / split at 1100, 1280 and 1440 px.
  - **AI status chip** at the end of the planner status bar and the model editor status line; **"Every command ⌘K"** on the ribbon (focuses the top bar's tool search) replaces the ribbon Ask box.
  - Tests: `tests/pro_shell.test.mjs` — every tool a Cmd example names exists in that editor's catalog (en + he), the AI switch, the mounts, Share's tab.

- **Round-5 AI grounding** (`js/agent_grounding.js`, pure; UI in `js/ui_agent.js`, plan drawing in `js/agent_preview.js`). Every AI proposal card now:
  - **names what the AI picked** — "Move Sofa F8 → Living room", "New door on wall W3", "New wall · 3.20 m" — by part code (see **Part codes** below), and pins the same **name tags on the plan**;
  - **checks it against the live plan before Apply**: overlaps (with height bands, so a ceiling light over the sofa is not a clash; non-blocking rugs ignored; a batch checks its pieces against each other), crossing a wall, standing in a door's swing, which room it lands in / outside every room, wall length, room area. Checks are advisory — the command layer still refuses anything invalid. A card waiting for an answer is re-checked on `vspan:ready` (before three.js loads every item reads as floor-standing);
  - **shows every lettered candidate at once** (A–D) instead of the old 1-second carousel: the focused one solid, the others dimmed, each with its tags and an "All checks pass / n to review" summary; a letter only focuses, **Apply A** applies; ←/→ move between them; the plan pans (zooming out only if needed) so every candidate is in view and not under the helper;
  - after Apply offers **Undo** (only while the AI's step is still the latest history step — otherwise it says to use the history) and **Adjust by hand** (selects exactly what the AI created or changed, Select tool, helper closed);
  - words the common refusals (`PERMISSION_DENIED`, `ITEM_LOCKED`, stale preview) instead of showing the code.
  - **AI vs you in the history**: steps labelled `AI: …` by `executePlannerProposal` wear an **AI** badge and read like your own steps ("Changed · Sofa").
  - Tests: `tests/agent_grounding.test.mjs` (geometry + wiring); `tests/agent_helper.browser.mjs` updated for the new card (letters focus, Apply applies, no carousel, Undo/Adjust after Apply).

- **Fold tool rail** (unfolded foldables / touch tablets, `body.dock-rail`): a 64px rail of the planner's nine catalog tabs is a column of `#workspace` before the canvas (`js/mobile_shell.js`), so the plan narrows instead of being covered. A tab docks "<Tab> · all tools · n" — the tab's grid from the pro catalog (`window.__proToolTabs`, `js/pro_ribbon.js`) — at the head of the docked inspector column, which widens toward half the screen; the inspector keeps the rest. Tapping the tab again or ✕ closes the tools (and the column, if it was opened only for them); the armed tool is highlighted in the grid. Running a tool through the hidden `#plan-toolbar` no longer counts as a tap on the plan that closes docked panels (`ui.js`, `mobile_shell.js`). Test posture in a desktop browser by overriding `navigator.maxTouchPoints` and firing `resize`.

- **Pro inspector (phone / fold)**: an identity card heads the inspector sheet or docked column (`syncInspectorCard` in `js/mobile_shell.js`) — kind icon, name, where it is (real room names only; wall phase; "on wall #4" for openings; gross area for rooms) and the same `#id` badge the AI tags and the history use (none for rooms, whose key is a wall list). The wall's five tabs show their labels under the icons (Size · Assembly · Openings · Constraints · Finish). The rest of the phone inspector already matched the mockup: walls own tabs, other kinds are one scrolling form, and the sheet leaves the plan visible above it.

- **Fold rails in the model editor and cabinet designer** (`js/modeler_mobile.js`, `js/ui_cabinet_mobile.js`): the same rail from the same catalog — model editor Sketch · Features · Reference · Assembly · Evaluate · Toolbox · Drawing · Appearance · Output, cabinet designer Design · View · Review · Production — as the first column of `.md-body` / `.cb-body`; a tab docks its tools at the head of that editor's Properties column. Model editor: while the tools show the tree column steps aside (your Tree preference is untouched), the sheet has no backdrop and the model narrows beside it; a command that opens a feature form closes the tools and brings the tree back with the form; `closeModelerSheet()` (called when a command needs the canvas) leaves the fold pane open since it covers nothing. The grid marks each editor's armed command (`mcmd:` → `#modeler [data-command].on`, `cab:` → `#cabdes [data-…].on`). Two fold layouts that were already wrong are fixed: the model editor's Properties/Commands sheet was full-width on folds (a later phone `@media (max-width: 1024px)` block re-laid `#md-sheet` as a bottom sheet), and the cabinet designer's docked panels overflowed the body and clipped the lower half of Properties.

- **Cabinet designer status bar** (`fillStatusBar` in `js/ui_cabinet.js`, refreshed by every edit through `changed()`): the recorded shop convention (or "No production convention"), units, carcass stock, sheets and yield from a real `nest(panelsOf([item]))` run, the part count, and the AI chip. The mockup's revision line needs a production job and is not shown. Desktop only; the compact layout keeps its own chrome.

- **Cabinet designer Split view** (`setMode("split")` in `js/ui_cabinet_view.js`): a third button under 2D · 3D. The elevation keeps the left half (`E.mode` stays `"2d"`, so every partition tool and view direction works as in the drawing, and picking a direction keeps the split) and the one borrowed WebGL renderer fills the right half, so an edit shows in the round at once. The drawing keeps clear of the view picker there (`gut`), the four partition tools become one row of icons, and the big view pulls back for the tall narrow pane (`bigZoom` may now be a function in `createEditorView`). PNG export always draws the whole elevation. Not on phones: the button is hidden in the compact layout and a split falls back to the drawing. Also fixed on the way, for every editor that swaps its renderer (`createViewportSwap`): the canvas kept its old size after moving between the panel and the big pane until the window was resized.

- **Model editor Split view** (`setMode("split")` in `js/modeler.js`, button `#mdModeSplit` after Drawing): the sketch on the left half, the model on the right. `E.mode` stays `"2d"`, so every sketch tool, relation and dimension works as in Sketch; the one renderer sits in the right half, where it orbits, zooms and shows each rebuild. Split starts a sketch the way Sketch does. Anything that needs the full model leaves it: finishing the sketch, the Model or Drawing buttons, switching to an assembly (`setDocumentType` goes through `setMode("3d")`), or the window becoming a phone (the sketch canvas's ResizeObserver). A workflow that asks for `"2d"` keeps it.
  - **The model half draws the sketches.** The 3D view never draws a sketch itself (in Model mode the sketch canvas is laid over it), so `syncSplitSketch3D()` samples every sketch on its own plane (`sketchUvPolylines` + `framePoint`) into a group of its own, from `drawSketch()`, rebuilt only when the geometry changed. The sketch being edited is bright, the others dim; the group is dropped when Split is left.
  - **Framing:** with no solid yet, `fitPreview()` frames a stock 60-unit box whose middle floats above the sketch plane, so `fitSplitPreview()` frames the sketches instead (once on entering, once when the first geometry appears). Halving the sketch pane keeps the user's zoom and re-centres rather than refitting.
  - Both editors' splits are in the pro catalog (`mclick:#mdModeSplit`, `cab:mode:split`), so the command bar and the fold rails reach them.

- **AI in the model editor and cabinet designer bars** (`js/editor_agent.js` loop and rules, `js/editor_agent_ui.js` card, adapters in `js/ui_cabinet_agent.js` and at the end of `js/modeler.js`). Same rules as the planner's helper, same settings (the planner's AI helper settings; the one transport, `sendAgentChat`): the AI only **prepares** — every change is a proposal on a card above the bar that names what it picked, and nothing changes until **Apply**. AI off, or no model set up, and the bar stays fully manual (it says so and keeps the text).
  - Shared tools: `get_editor_state`, `search_editor_commands` (that editor's pro catalog) and `propose_command` — "open Fillet — radius 8 mm on the top edges": Apply opens the editor's own command, and the card says it opened and what to enter.
  - **Cabinet designer** direct proposals, in mm, through the designer's own code: `propose_size` (the size inputs + `applyOverallSize`, so its size check and re-plan dialog run), `propose_compartment` (column/compartment 1-based, compartment 1 at the bottom; `applySecType` and the inspector's count ranges), `propose_door`. Previewing selects the compartment so it is outlined on the elevation. Steps are labelled `AI: …` for the history's AI badge.
  - **Model editor** direct proposal: `propose_variable` — a global variable's new expression, tried against the equations first (`BAD_EXPRESSION` is refused before the card), applied as one undo step. Features and sketch edits are `propose_command`: their forms stay the user's.
  - **Undo** on the card takes back exactly the steps the change made; when the designer is still asking how to re-plan a size, the card points to Undo / the history instead, because that choice lands on top.
  - Tests: `tests/editor_agent.test.mjs` (the loop with a scripted model: proposals only, failures reported back, JSON never shown, bounded rounds; the adapters' wiring). Checked in the browser with a stubbed endpoint: size + shelves + door, a pull-out change plus a command, Undo restoring the cabinet exactly, and the model editor's Extrude.

- **Part codes** (`js/part_codes.js`, pure). **Decided (owner, 2026-09-26): a code is a letter for the kind plus the object's real id, never a per-floor renumbering** — W wall, D door, WN window, O other opening, F furniture (cabinets too, so converting a piece in the designer does not rename it). Ids come from the one counter `S.idc`, so a code is unique and never changes while the object exists; deleting a part leaves a gap. Where they appear:
  - the AI card, its plan and 3D tags and its checks ("Overlaps Armchair F13", "In the swing of door D7", "Crosses wall W3");
  - the AI's context: `code` on every wall, opening and item in `entities` and `spatial`, and the workflow prompt says what the letters mean and that command params still take the numeric id;
  - the phone / fold inspector card and a code chip beside "Inspector" on desktop;
  - **on the plan** — View & render → **Part codes** (`pro:partCodes`, remembered in localStorage `mf.partCodes`, off by default): a small tag on every wall, opening and piece, the selected one in the accent colour (`js/part_code_labels.js`, an SVG over the plan like the AI candidates, never in exports or print);
  - **typed into the bottom bar** (either mode, AI on or off): "F13", "wn 6" or "#13" selects that part and brings it into view; a lettered code that names nothing here says "No D12 on this floor" instead of going to the AI.
  - Tests: `tests/part_codes.test.mjs`.

## What is NOT done (next steps)

1. **The model editor and cabinet designer keep their own ribbons.** The editor switcher is shared now (see `js/pro_shell.js` above), but the model editor ribbon was deliberately not restructured (saved uikit layouts and browser tests key on its groups — `grpDirect/grpReferences/grpStandards`), and parts of the Round-6 shell are still missing: the right-hand preview + tabbed inspector layout of the mockups.
2. **AI grounding — what is left.** Name tags and candidates are drawn on the plan **and in 3D** (`paint3D` in `js/agent_preview.js`, on the planner's 3D overlay canvas via `planner-overlay-3d` — boxes at each item's real height and elevation, a ghost wall for new walls, an upright frame in the host wall's plane for openings, the focused candidate solid and orange when its checks warn, the others faint; nothing is added to the THREE scene). Tags use the part codes (below). **Decided (owner, 2026-09-26): the AI is exempt from the work-set rule.** `aiCanMove()` in `js/layers.js` ignores which layer is being edited and its automatic lock (`autoLock`), but still stops at a padlock set by hand and at a pinned object. Only the AI's paths pass `{ ai: true }` (`agent_runtime.js` previews, the WebMCP bridge, `ui_agent.js` apply); the layout tools and your own drags keep the rule.
3. **Fold rails — done in all three editors.** The mockups' label | value inspector rows were not adopted — the existing two-column field grid stays.
4. ~~`workspace.js` keeps its own copy of the sheet-print helper~~ — done: it calls `printSheetSVG` from `sheet_print.js`.
5. **`npm test` is not green on this branch, and on Windows it looks worse than it is.** Many source-contract tests read `js/*.js` with regexes that expect LF; a Windows checkout (`core.autocrlf=true`) has CRLF, so they fail or crash whole files (`review_second_batch` fails at load). With LF copies of the files they read, failures drop from ≈33 to ≈13 of 3,235 — the repo stores LF, so Linux CI sees the lower number. What remains is real: kernel-body/pattern contracts (`kernel_body_finish`, `cad_pattern_merge`, `cad_body_ops`, `review_second_batch` "axis cuts follow framed and primitive hosts") and a few planner files. `material_density_assignment` can time out under a loaded full run but passes alone. None of this is from the pro shell; `npm run check` is green.
6. Verify in a real browser after any change: `npm start`, then desktop + phone viewport; `npm run check` must stay green (a broken import silently kills the UI).
