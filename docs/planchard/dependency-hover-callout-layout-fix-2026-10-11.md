# Stable dynamic-reference hover layout

Actual Chrome exposed a presentation bug: reference callouts were appended inside the control panel above the tree. Hovering Boss2 grew that panel, shifted the hovered row from Y774 toY954, and caused a real mouseleave that immediately cleared the visualization. The same layout could affect mate hovering.

Callouts now live directly under the modeler root as a fixed, bounded overlay positioned beside the controls. Only the unchanged Parent/Child controls consume tree layout space. The overlay is pointer-transparent so it cannot steal the hovered row; it is hidden when empty, retains the text floor and recomputes its viewport-clamped position with arrow redraw on scroll/resize. Genuine graph, topology/occurrence identities, role assignment, named collapsed-reference labels and SVG tree arrows remain unchanged.

It does not claim a full browser layout engine from the Node fixture; actual settled Chrome hover acceptance remains parent-owned.
