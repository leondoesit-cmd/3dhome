## Bounded real slicing algorithm proposal — separate future implementation

Repository presently exports geometry and print placement but has no STL/AMF/3MF import, slice plane intersection, layer connectivity, shell offsets, infill clipping, support generation or nozzle toolpath. This is a genuine digital workflow gap. A narrow honest first step is a **read-only layer contour preview** on an existing prepared native triangle mesh: choose positive layer height; intersect every triangle with horizontal Z planes; handle on-plane vertices with a consistent half-open rule; weld intersection endpoints using an explicit tolerance; join closed contours; show actual selected-layer polygons and flag unclosed/degenerate contours; save a layer-analysis JSON/SVG with source fingerprint and print transform. Meaningful tests must cover exact box/cylinder/annulus cross-sections, counterbore shoulder layer transitions, multipart disconnected loops, vertex/coplanar degeneracies, thin features, oversized layer counts, units and stale geometry invalidation. This could establish genuine geometric layers; it must be labeled **layer analysis**, not full slicing/toolpaths or printable G-code.

Adding perimeters/infill/support afterward requires robust polygon operations, hole ownership, bed contact/overhang access and an identified printer/material profile. Arbitrary G-code from line contours would exceed the evidence. A real browser-accessible slicer handoff remains the shortest route to full source slicer workflow acceptance. Physical leveling/adhesion/cleanup, printer monitoring, actual fit/strength and certification cannot be completed by software records alone.

## Implemented genuine layer analysis — actual browser acceptance pending

The bounded geometric proposal is now implemented in `js/core/print_layer_analysis.js`. **Layer analysis** is available in command search and the part Output / assembly File ribbon. It requires an existing saved **Print setup**, validates/tessellates the real native body at Custom0.01 mm/5°, applies the same saved orientation/centered/bed placement as print export, then calculates horizontal cross-sections at each layer slab midpoint. Assembly worker mode returns separately validated native occurrence meshes after the exact composed poses and global print transform; source identities remain separate.

The UI has **Layer height (mm)**, **Selected layer**, **Apply**, **Export layer analysis JSON** and **Export selected layer SVG**. Apply retains the dialog, showing actual layer count, section Z, closed contour/hole counts and material area. Layer selection previews the computed polygons. Hole nesting and orientation are calculated geometrically; redundant triangulation-edge points are simplified. Section vertices on the plane use a half-open convention; coplanar facets use adjacent boundaries. Open/branching/duplicate/degenerate contours fail explicitly, as do open or inconsistently oriented source meshes. Weld tolerance is0.00001 mm; at most2000 layers,100000 source triangles and20million triangle-section attempts. Increase layer height if that budget is exceeded. Selected SVG and full JSON include genuine computed geometry; JSON retains mm/Z-up qualification, source mesh fingerprint, print setup and tessellation settings.

No Undo entry, print settings, source sketches/features/poses/mates or library model is mutated. The source/orientation/document/dialog guard blocks stale output before and after cooperative calculation and before download; changing layer height requires another Apply before export. Canonical derived rebuild/cache fields are excluded from that guard, while direct-document primitive dimensions still invalidate it. The result remains explicitly **geometric layer analysis**, not a complete slicer, infill/support, nozzle paths or G-code. Actual browser acceptance and a one-parameter layer-height comparison remain parent-owned.
