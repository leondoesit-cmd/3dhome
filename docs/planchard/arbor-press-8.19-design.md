## Native app gap and representation

Source inspection finds no rack-and-pinion mate in `js/cad_mate_model.js`: current gear/belt relationships couple two angular axes, while Screw requires coaxial frames. A screw substitution would misrepresent this mechanism. The source solver agent is adding a dedicated rack mate; assembly authoring must wait for that visible command, persistence, physical residual and Drive support to pass focused tests and gates.

The original educational model uses an ideal rack-and-pinion kinematic relationship, a smooth pinion outer envelope and a square ram. Manufactured involute rack/pinion teeth are deliberately omitted and must be disclosed in Description and drawing notes. Native ratio coupling is required; coincident solids or animation keyframes alone do not establish a mechanism. A later tooth-geometry enhancement would require separately verified tooth clearance/contact; it must not silently reuse this smooth-envelope clearance acceptance.
