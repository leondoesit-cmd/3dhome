# Kant Twist 8.18 native mate preflight

Source-only preparation for the frozen `kant-twist-8.18-design.md` layout. This note does not certify the authored 25-occurrence assembly, its physical one-DOF path or its clearance. Those require parent-owned Chrome construction and native audits after all parts are saved.

## Available primitives and evidence

`cad_mate_model.js` requires an actual axis frame for Concentric/Screw and actual planar frames for Limit. Exact circular cylinder axes are eligible even when native centroids differ along their axis. Named Front/Top/Right datums provide stable planar references; select them explicitly in Reference A/B rather than substituting a bounding face. Use the current exact axes after source regeneration and confirm the picked bore/journal by position and direction.

Concentric preserves the equivalent opposed native axis orientation and permits axial translation plus roll. A datum Distance captures axial translation while preserving roll. A coupled Screw aligns axes and couples component-origin axial separation to relative phase; it deliberately does not use a cylinder face centroid as its axial zero. New UI screws default coupled/free, with Drive turns blank. A signed Limit measures B-origin minus A-origin along A's transformed normal and retains the specified aligned/opposed orientation. Its unequal bounds are inequalities, so the stop does not consume the available return motion.

Bounded current-source checks: 8 selected tests pass across `cad_closed_loop_mates.test.mjs`, `cad_coupled_screw_mate.test.mjs` and `planchard_limit_mate.test.mjs`. These exercise a grounded four-bar, chain decomposition, coupled screw winding/reopen, a swiveling screw-driven closed loop, signed limits and both stops. These are synthetic solver fixtures, not this assembly. The actual vice atomic drive/reopen regression is separate evidence; neither establishes acceptance of the Kant loop.

## Recommended Chrome order

1. Place all occurrences at the frozen open coordinates, retaining Z offsets and component origins. Ground KT01 identity. Save this unmated home checkpoint.
2. Positive BraceA: Base P bore axis A / BraceA P bore axis B → Concentric; Base Q bore / BraceA Q bore → Concentric. Base Front datum / positive BraceA Front datum → Distance 0 mm. These physically support the fixed outer arm at two separated pins. Lock the correctly placed negative BraceA to positive BraceA, preserving its −37 mm origin offset. Do not use a lock to repair misplaced components.
3. Lock the correctly placed P/Q/JA PinA occurrences and their retainers to their fixed support group. Keep the common JB PinA separate until the moving inner group is formed.
4. Main P PinA exact Z axis A / positive BraceB P bore Z axis B → Concentric; Base Front / positive BraceB Front → Distance 0 mm. This leaves inner-arm rotation about Z. Lock negative BraceB to positive BraceB at its −25 mm origin offset. Lock JB PinA, its retainer and spacer sleeves to that moving brace group at their frozen home placements.
5. Positive BraceA RA journal bore A / HingeA integral Z journal B → Concentric; BraceA Front / HingeA Front → Distance 0 mm. Positive BraceB RB journal bore A / HingeB integral Z journal B → Concentric; BraceB Front / HingeB Front → Distance 0 mm. Each trunnion retains Z yaw. Lock each KT08 cap to its own trunnion. Do not lock a trunnion to a brace.
6. HingeA actual local-Y bore axis A / Shaft actual local-Y shaft axis B → Concentric. HingeA Top datum / Shaft Top datum → Distance 0 mm. Choose aligned datum orientation at home: both origins are RA. This captures axial origin while leaving spindle roll and trunnion yaw. Lock handle bar/grip/grip screw to the correctly placed shaft group.
7. HingeB threaded-bore axis A / Shaft axis B → Screw. Keep Couple screw rotation and travel checked, set Pitch (mm/turn) to 2 and press Enter, leave Drive turns blank. Inspect axes aligned/opposed and establish the correct native direction at the saved home before driving. Keep the captured zero; do not toggle coupling to manufacture a convenient winding after motion.
8. GripA/GripB: their own JA/JB pin Z axis A / jaw bore Z axis B → Concentric, then support Front / jaw Front → Distance 0 mm. Base or assembly Top datum / each jaw Top datum → **Angle 0°** for the disclosed flat-workpiece configuration. The PropertyManager now also offers **Parallel planes (0° angle)** as an explicit shortcut to that same native Angle mate. This changes orientation only, preserving the separated datum origins; it does not add Coincident or Distance. The saved history honestly remains an Angle mate with value 0. This preserves jaw faces globally parallel while the lower brace rotates. Removing these two guides is a separate unrestricted configuration with additional freedoms.
9. HingeA Top datum A / HingeB Top datum B → Limit, aligned. Enter Minimum travel **69.570108523704 mm**, Maximum travel **90 mm** in the Mate PropertyManager before Apply. These origins are RA/RB and normals remain +u, so the signed span is L, not cylinder-centroid separation. Add this only after the closure geometry is consistent.
10. Save/reopen and require zero missing references or unsatisfied mates. Blank drive should leave one actuator DOF in the guided-jaw mechanism; a specified drive should leave zero. Make a small measured trial, verify RB/JB coordinates and gap against the frozen table, and establish closing sign in Chrome. Do not infer it from native face arrows. Use quarter-turn increments toward 10.214945738148 closing-progress turns, check both beyond-limit failures atomically, return open and clear Drive. Preserve checkpoints before full motion/exact interference acceptance.

Reference A/B order above expresses intended signed directions. Closed-loop solving can move both ungrounded components; A is not an instruction to ground the reader. Hardware locks capture the already correct relative transform. Add one group/joint at a time and resolve a mismatch before adding further constraints.

## Concrete creation gap repaired

Before this audit, `addTopologyMate('limit')` always stored 0..2 cm and immediately solved, while `openMatePropertyManager` offered no Limit min/max fields. At the 90 mm open span, this would first ask for a 20 mm cap before the inspector could be edited.

The PropertyManager now exposes Minimum/Maximum travel for Type Limit, uses the existing active-document length parser, and passes both bounds into canonical creation. `validLimitMateBounds` rejects blank/nonfinite/reversed bounds before history, mate allocation or solve. Defaults remain 0..20 mm; signed/equal ranges remain supported. A 90 mm synthetic datum fixture invokes the actual PropertyManager callback and native creation/solve, confirming the first solve sees 69.570108523704..90 mm and preserves home. No authored part or assembly JSON was changed.

There is no further demonstrated unsupported primitive from this source audit. Native axis availability, stable winding through simultaneous yaw/roll, exact whole-loop DOF and physical clash acceptance remain browser-validation tasks, not presumed successes.

The first Chrome assembly pass exposed a discovery gap in this note's earlier recommendation: native Parallel was not a separate mate type. The existing Angle 0° provides the required same-direction planar orientation relation without translation capture. The Type shortcut above was added after that observed gap. Focused actual PropertyManager/creation callbacks verify native Angle 0 storage/reopen, unchanged free-body translation, and removal of exactly the remaining pin-jaw swivel freedom. Parent-owned browser validation of the shortcut remains required; no stored Kant assembly was edited by this source repair.

## Existing insertion, placement and reference UI

This source inspection covers the actual native controls; use the current Chrome DOM/screenshot to confirm their visible location before interacting.

- **Assembly** switches to the assembly document. **Components** opens the component tree and insertion panel. The native library dropdown has accessible label **Component model**, with each saved document's full name as its option caption. **Insert component** creates one fresh occurrence of the chosen saved definition. The dropdown retains its chosen model across refreshes, so duplicate occurrences can be inserted without reselecting the source. No prior assembly or Toolbox model is needed.
- Insert **KT01 first**: the first occurrence is grounded automatically at identity. Later insertions are free and receive temporary X = occurrence index × 250 mm. Place each new occurrence immediately, then insert the next, so temporary spacing does not dominate Zoom to fit for the whole 25-occurrence assembly. Insertion selects the new occurrence automatically.
- The right inspector's assembly tabs are **Placement**, **Component**, **Mates**. Placement shows **Part name**, **Component description**, **Component part number**, and **Transform**. Use unique occurrence names such as `KT03 BraceA +Z` and `KT03 BraceA -Z`; the source PartNo remains inherited unless explicitly overridden. Commit names with Enter. Avoid overriding the BOM part number with the occurrence name.
- Placement numeric labels in a mm assembly are **X (mm)**, **Y (mm)**, **Z (mm)**, **RX°**, **RY°**, **RZ°**. These six inputs are deliberately staged: filling/Enter does not apply a pose. Fill all needed fields, then click **Apply placement**. It converts translation from document units, commits one placement edit, drives the selected component for the solve and restores the prior pose if its mates conflict. Rotation values are degrees. A grounded component's Apply placement is disabled; its Component tab **Grounded** checkbox or tree context menu can change grounding when deliberately required. Keep KT01 grounded.
- Tree component selection is ordinary click; **Ctrl-click** adds/removes another component. Select A then Ctrl-select B to establish the pair. With that pair selected, **Mates** inspector exposes native dropdowns whose accessible labels are **Reference A · [occurrence name]** and **Reference B · [occurrence name]**. Reacquire the dropdown after changing a reference: the inspector rebuild is deferred to the next animation frame. Source-generated option values are persistent topology IDs; select an observed actual option, not an invented ID.
- The reference chooser orders **Exact axis** choices first, then native cylindrical/circular references, then native planar faces and named datums. Labels include producing feature, radius and **local source-document** X/Y/Z in current units. They are not world assembly coordinates. For BraceA P/Q/JA/RA, identify the bore using its original local coordinates; the occurrence's Y150 placement does not change those option labels. For a journal's repeated coaxial cylindrical faces, use the matching axis line and correct Z section/radius; selecting a different cylinder centroid along the same axis must not substitute for the datum Distance that captures axial location.
- **Front Plane**, **Top Plane**, **Right Plane** are always available per occurrence in the tree. The native selector captions identify the same datums by **plane:front**, **plane:top**, **plane:right** within their displayed face label. These are stable datums, not exact cylinder-centroid planes. The assembly's own datums are available in its tree. Tree plane selection can be Ctrl-additive. For the guided jaws, using Base Top as the grounded orientation datum avoids confusing an occurrence plane with the assembly origin.
- A chooser with only named datums has not proved that the current exact face index is available. **Refresh exact mate references · [occurrence name]** is an explicit native regeneration control. Wait for the fresh choices rather than mating a mesh/bounding-box substitute. Current component-edit Finish also awaits native regeneration before publishing the source back to the assembly.
- After selecting references, **Mates** on the Assembly ribbon/Cmd opens the PropertyManager, whose Type choices depend on the real reference frames. Its **Reference A/B** text rows report the picks and are read-only. Choose the type and parameters, then **Apply**. For a nondefault Limit, use this PropertyManager and enter both bounds before Apply; the compact direct **Limit** palette action retains legacy 0..20 mm defaults. Use actual axis references for Screw and actual Top datums for the signed span Limit.
- Save component groups/checkpoints regularly with **Save assembly**. Library snapshots copy the saved sources and placements, so changing a part library record later does not silently alter an existing occurrence. **Update from library** is an explicit occurrence action that rebuilds/solves; use it only for an intentional source update and verify references afterward.

No new source repair was justified by this insertion audit. The staged placement, retained insertion choice, unique occurrence rename, exact selectors and native reference-refresh routes already exist. Actual usability/performance with this 25-occurrence assembly remains a Chrome validation task.
