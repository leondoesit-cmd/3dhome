## What configuration rebuilding actually does

`setCircularSweepDesignTable` validates row values and stable table source IDs, updates all `configuration.designTableValues`, retains active row and invokes `setActiveConfiguration`. `applyCircularSweepRow` rewrites the active path circle/diameter constraint and sweep circular profile/generated path, updates matching kernel part sources and removes stale mesh. UI `refreshConfigurationGeometry` calls refreshAll, schedules cleared circular-sweep kernel parts, and schedules exact restore for canonical authoring. Entering Drawing always invalidates projections; incoming exact meshes also invalidate via `refreshChangedPart`. Thus active configuration native rebuild is scheduled by ordinary commands rather than inferred from a label.

**Important finite qualification:** `configuredBodiesForView` constructs each named ring view from its source row and sketch frame as a64×20 triangulated torus. It does **not** rebuild a separate native BREP for every nonactive configuration view. This is genuine parameter-associated circular-path/circular-profile configured geometry, with finite sampling, not a certified native configured-edge projection. Existing tests prove different row diameters and labels; they do not prove the actual browser driver. Other shapes/invalid source IDs fall back to active bodies and must not be accepted as independent named native geometry. The current valid source matches required IDs/circular-sweep type; verify actual browser dimensions/bounds, row isolation and restoration before acceptance.

Source plane/geometry identity remains untouched by sheet cleanup, metadata, material/style/layout. The temporary driver changes exactly the intended row then Undo restores it.
