# Thread from a full circular boundary edge

Confirmed source-workflow gap: official Exercise 5.16 uses a circular edge to start a cosmetic thread. The app previously accepted only cylindrical faces. The existing face route remains available; Helix, Knurl and Insert face selection are unchanged.

Thread now accepts one selected full circular boundary edge on the selected body's current native topology. The selector first requires its exact persistent ID and owner to exist in that body's topology. It validates circumference, finite center/radius/axis, and exactly one equal-radius coaxial cylindrical face whose native axial range ends at that center. The picked end supplies the thread origin; direction points into that cylindrical range. Native range information is required, so a planar circular cap alone, an arc, an interior circle, stale ID or geometry, unsupported analytic descriptor, wrong-radius/axis face or ambiguous host is rejected. No nearest/fuzzy face lookup or world-axis default was added.

The stored feature retains both the native cylinder-face and edge references, canonicalized using the existing input-stage mechanism. The ordinary Thread readiness and live selection feedback use the same resolver as Finish. Choose the circular edge alone (clear an existing face selection first), open Thread, select the intended specification/side/mode/length, then Finish. A preselected cylindrical face continues using its established start placement. For the chosen +Y shaft witness, the free edge at Y=0 produces inward +Y; picking the far end produces −Y.

This is validated initial start/axis selection. Placement remains explicit feature parameters as in the existing face route; this patch does not claim a new general associative thread-placement solver or recovered original SOLIDWORKS persistent IDs. Cosmetic threads remain annotations and do not cut the native solid. Existing modeled-thread behavior is preserved rather than newly qualified here.
