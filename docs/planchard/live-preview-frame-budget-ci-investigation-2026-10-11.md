## Final idle diagnosis and bounded repair

After full CI exited, both other agents held browser work for an idle elevated rerun. The unchanged original file passed5/6: kernel functional/debounce tick test passed, but analytic11-copy steady mean16.56/worst23.30ms still failed. Kernel mean13.38/worst16.50ms was also outside the timing test's maximum guard. Thus concurrent load amplified a real remaining lifecycle cost.

Idle profiling attributed repeated synchronous shader/program work to `cadEditFeatureParams → refreshLivePreview → patchEditedFeatureLayer/patchLivePreviewLayer → render`. Both partial paths disposed the obsolete materials before rendering replacements, releasing the last matching shader-program references and forcing recompilation. Sampling under that exact call stack assigned77.6ms analytic and93.6ms kernel to `getProgramInfoLog` across12 profiled edits; profiling itself adds overhead, so these are attribution data rather than post-repair timing claims.

New `js/core/gpu_child_retirement.js` detaches only the obsolete children into an off-scene group immediately, performs the replacement/render while those old material program references remain alive, and disposes the retired geometry/materials in `finally`. Bounded integration changes only `patchEditedFeatureLayer` and `patchLivePreviewLayer`. The committed predicate excludes the live group; nested retirement releases ghosts and committed bodies after the same replacement render. Removed meshes are absent from active scene bounds/picking immediately. Cleanup also runs if replacement rendering throws. The full refresh, native worker, canonical document, debounce delay and other disposal routes are unchanged; there is no unbounded material cache or deferred timer.
