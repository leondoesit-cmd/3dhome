# Exercise 5.17: functional position and profile sketch integration

Date: 2026-10-10. Scope: source/code architecture inspection only. This report does not implement or claim browser acceptance of the proposed objects. The parent is authoring the source-qualified base with 1060 Alloy separately.

## Source requirement and bounded scope

PDF pages 266-267 / printed 5-48-5-49 require a Hole Wizard counterbore on a cylindrical face, a position point constrained OnSurface, a 0.25 in distance from the top face, a top-face construction line from the cylinder axis with Along Z, and Along Y between its endpoint and the hole position. Page 267 explicitly identifies **two fully defined sketches: hole profile and feature position**. Only the position is the 3D sketch. A real local planar axial profile, attached through a 3D frame, satisfies the second sketch requirement; inventing another 3D point sketch would misread the source.

The safe finite extension is one straight Y-axis cylindrical placement sketch and one counterbore axial profile sketch. Keep its scope explicit in the editor. Do not advertise a general arbitrary-face 3D sketch solver. Do not convert an old equivalent hole into a book-complete workflow merely by adding history labels.

## Persisted objects and ownership

Store the position in `definition.sketches`, with a stable `id`, `kind: cylindrical-position-3d`, `sketchSchemaVersion: 1`, `frameSpace: world-3d`, internal units cm, and a source record containing the existing base feature ID, circle ID and persistent cylindrical face reference. A compatible `referenceId`/support record must still address its real support. Persist authored XYZ points A/B/P, one construction line A-B, one non-construction point P, relation definitions, the top-distance dimension and branch choice. Store diagnostics separately as recomputable results; diagnostics must not be the sole model.

A is the top axial centre; B is the top-face radial endpoint; P is the hole position. The genuine relations are axis-centre coincidence, B on the top plane, A-B Along Z, P OnSurface, top-face distance, and B-P Along Y. For this finite family, retain positive/negative Z branch identity so an upstream rebuild cannot silently flip sides. The source face must belong to the cylinder base feature, not the downstream cut face generated by this hole.

Store the profile as a distinct `kind: hole-counterbore-profile`, `sketchSchemaVersion: 1`, `frameSpace: local` sketch with stable points and line entities forming an axial half-section. Its radius step and head depth must be real driving dimensions; a displayed circle with metadata that the cutter ignores is insufficient. Use a plane through the hole axis: local axial coordinate points inward, local radial coordinate lies tangent to the cylinder, normal completes the right-handed frame. Regenerate the frame from the position sketch. Record the placement-sketch dependency explicitly.

For through-all, distinguish the authored through-all end condition from the computed body-intersection extent. The final extent used to close the displayed profile is derived/reference geometry, not a second conflicting user depth dimension. Counterbore bore diameter, head diameter and head clearance/depth remain editable dimensions, respecting current ANSI table defaults and custom-size qualification. Define whether head clearance or total recess depth is driving; do not drive both redundantly.

The hole references both sketches: `references.sketches = [positionId, profileId]`, plus its target/base feature references. Add explicit `params.positionSketchId` and `params.holeProfileSketchId`; keep `params.sketchId` compatibility unambiguous, preferably the profile ID for the new subtype. The feature's normalized numeric size/placement fields are derived compatibility mirrors, not competing authorities. Exports, callout, preview and native kernel all consume the same resolved input.

Do not make the sketches depend on their own consuming hole feature. Their owning relationship is UI grouping only. History order is base sketch, base extrude, position sketch, profile sketch, hole. Position depends on base extrude; profile depends on position; hole depends on both and the base. This is acyclic. Separate physical dependency from visual absorbed-child grouping.

## Solver and editing behavior

A closed-form solver is adequate for this bounded relation family, provided it solves the persisted definitions and treats diagnostics honestly. With all source relations enabled it produces the unique branch solution. With a relation removed, preserve authored free coordinates or solve the remaining equations; report positive DOF and prevent creation/rebuild of a hole that requires fully defined placement. Do not silently reconstruct the removed relation by always assigning the analytic fully constrained coordinates. Validate edited coordinates and contradictory dimensions with residuals, rank and finite bounds. Either support free-coordinate dragging in this finite model or explicitly restrict its editor to dimensions/relations and branch; the latter is acceptable when stated clearly.

History Edit on the position opens a dedicated 3D editor with real XYZ construction and point geometry, relation selection/suppression, top-distance entry and visible DOF. Selecting P highlights its surface reference; selecting A-B highlights Along Z; selecting B/P highlights Along Y. Cancel restores the entire document snapshot; Finish solves and atomically rebuilds or keeps a diagnosed rejected preview. General planar sketch commands must be unavailable in this subtype until they support world XYZ.

History Edit on the profile exposes its actual contour and diameter/head dimensions in its local 3D frame. Editing one supported dimension must change the native cutter and callout after Finish. A standards change in the Hole Wizard updates the same driving profile dimensions transactionally. If both entry points exist, they edit the same source fields. Avoid bidirectional synchronization loops and stale mm/cm aliases: `cad_hole_wizard.js:pickMm` currently gives explicit millimetre fields priority over centimetre fields.

Use a shared resolver before native lowering, preview generation and compatibility cut refresh. It validates both sketch IDs, source owner and profile family; resolves placement; solves/refreshes the profile; derives normalized wizard dimensions; then calls existing `holeWizardSolids`. This preserves the proven native bore/counterbore subtraction pipeline. Invalid sketch input must produce a targeted error rather than fall back to old feature params. Both core and native paths must see identical dimensions and frame.

## Dependency, deletion and cold-load safeguards

Extend dependency analysis for sketch-to-feature and sketch-to-sketch references. Current `dependentTargetIds` only walks features; `historyDependents` only returns feature rows; `removeHistoryNode` inspects feature consumers. All must recognize profile-to-position and position-to-base dependencies. Base deletion must identify both sketches and the hole. Position deletion must identify profile and hole. Profile deletion must identify hole. Block destructive removal with dependants or present a concrete cascading removal operation; never leave orphan contours or stale exact meshes. Suppression must propagate these relations, and unsuppression must not revive explicitly suppressed children. Reordering/rollback must reject future support/sketch dependencies and cycles.

Invalidate exact topology/mesh caches when either sketch's authored fields or source geometry change. Existing rebuild signatures include sketch fields, but confirm each native worker/cache path receives the resolved input and relevant sketch revision. Refresh compatibility `cuts3d` as well as authoring features; `syncHoleCutPlacement` currently copies only centres/frame/support, so profile edits also require cutter dimension refresh or regeneration of all associated role records.

Use a top-level schema bump if unsupported-subtype handling is introduced as a project contract; otherwise an explicit versioned subtype plus import validation is still mandatory. Existing version-8 holes must continue to open with the parameter-only behavior and retain their exact body. Do not automatically synthesize a claimed user-authored sketch on load. Provide an explicit conversion action if useful; conversion produces functional objects and preserves cutter geometry, but remains conversion rather than historical browser authorship. Reject unknown sketch subtype versions with a readable diagnosis, preserve source data, and avoid coercing them to ordinary planar sketches.

Save both sketch definitions, authored constraints/dimensions, references and history. Cold load must recompute solver results, local profile frame, cutter and diagnostics from those saved objects. Persisted screenshots, geometry caches or old fully-defined labels are not evidence that the saved sketches solve correctly.
