# Cabinet review findings 26–50

Reviewed 12 September 2026. The supplied review was checked against the current implementation; a suggested fix was not assumed correct merely because it appeared in the report.

| Finding | Resolution |
| --- | --- |
| 26 — System 32 units | Already corrected. Regression checks distinguish the 32 mm grid from an erroneous 320 mm grid. |
| 27 — Runner screw direction | Generic anchors now share one height and are separated along panel depth on the 32 mm grid. Actual runners still require their selected hardware template. |
| 28 — External drawer fronts | Physical front boards now participate in drilling reports, including their handle holes. Drawer-to-front hardware fixing remains an explicit recipe requirement. |
| 29 — Fixed shelf connectors | Generic manufacturing output now raises a blocking `joinery-template` finding. A complete shop-authored recipe must specify face drilling and account for separately machined edge operations. No universal connector pattern is invented. Horizontal edge machining is not generated by the vertical-drilling posts. |
| 30 — Leather handle | Leather and knob handles have one fixing; bars have two 96 mm-spaced modeled fixing points and matching holes. |
| 31–32 — Corner plan swing | Plan symbols use the actual selected hinge, diagonal leaf reach and outward quarter-turn. |
| 33 — Lift plan arc | Lift doors have no horizontal opening arc. |
| 34 — Elevated collision warning | Door and furniture vertical intervals must overlap before a plan clearance warning is raised. |
| 35 — Corner clearance reach | Clearance and plan symbols use the same physical diagonal hinge geometry. Clearance checking still tests the 90-degree open leaf, not a continuous swept-volume collision simulation. |
| 36 — Corner opening phase | Corner doors use the common first-phase opening function. |
| 37 — Bi-fold rotation | The proposed sign reversal would break the geometry. The existing counter-rotation is correct because the second leaf's hinge translates with the first. Tests cover both hinge sides and intermediate opening positions, checking joint continuity and outward motion. |
| 38 — Trouser rails | Rails are spaced along depth at a common height. |
| 39 — Very short drawers | Impossible drawer boxes are omitted and reported as errors, rather than enlarged beyond their compartment. |
| 40 — Narrow TV niche | No forced minimum screen width; a niche that cannot contain the screen and bracket omits them. |
| 41–42 — Cabinet legs | Hardware quantities and indicative pricing match modeled legs. Rectangular units have supports beneath dividers and intermediate supports for long spans; corners receive polygon-based supports. This is a geometry/estimate rule, not structural load certification. |
| 43 — Flush plinth | Flush plinth aligns with the closed overlay door face. |
| 44 — Corner edge profile | Profile length uses the exposed worktop diagonal instead of a rectangular width plus returns. |
| 45 — Drawer box stock | Box sides/rear use the selected carcass panel thickness, keeping modeled parts and cutting stock consistent. |
| 46 — Sliding wardrobe hanging depth | Compact hanging is allowed from 50 cm clear depth, with a clearance warning below 55 cm. Hanger/clothing suitability still needs checking. |
| 47 — Lift height fit | Eligibility uses the covered door-run height, including when choosing a door for a currently doorless column. |
| 48 — Top compartment resize | Upper storage uses excess height above the main compartment and actual shelf thickness. Resizing from 205 to 206 cm no longer removes 50 cm from the main compartment. A useful minimum upper-compartment height remains. |
| 49 — Base cabinet top drawer | The top drawer is explicitly outside the lower door run. |
| 50 — Revert | Restore synchronizes the active cabinet definition and rebuilds linked instances, so cached geometry no longer retains the edited version. |

## Verification

`tests/cabinet_second_review.test.mjs` adds 20 grouped regression cases for the findings above. `tests/cabinet_second_review.browser.mjs` exercises the plan renderer in the full browser module graph, including unequal drawing scales and lift-door exclusion. Existing cabinet tests cover manufacturing validation, exports, editing, save/reload and linked instances.

- Full `npm test`: 2,536 tests passed, zero failures or skips.
- 94 cabinet unit tests passed.
- Six cabinet browser tests passed (the new plan test passed after correcting its test assertions).
- Live GPU-browser QA: 65 checks passed, including 336 geometry combinations. The standalone page skips persistence because it lacks the full application UI; the dedicated full-app browser test passed save/reload separately.
- Module identifiers, 465-module linking and 1,402 source assertions passed.

Physical CNC operation has not been tested. Generic drilling patterns are review inputs; machine/controller qualification, actual hardware templates, setup and a supervised test piece remain required before production.
